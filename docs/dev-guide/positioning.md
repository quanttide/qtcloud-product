# 产品定位与核心设计

> 2026-08-16 澄清。定位与核心设计是产品云的"根"，想法升级（见 [想法记录](ideas.md)）从这里生长。

## 定位

**量潮产品云是产品决策平台：集中管理和可视化所有产品，让产品决策从个人头脑变成共享视图。**

- 产品越来越多，产品决策越来越困难：做什么、投多少、何时做、依赖什么。
- 平台把每个产品的结构（用户故事地图、PRD、版本计划）、状态与决策记录集中沉淀，并提供跨产品的组合视图。
- QtCloud Studio 是平台的画布客户端；用户故事地图是单产品全景的核心组件，组合视图是它的上一级。

## 核心问题

产品云的根问题是：**不可见的东西变得可见，绑在人身上的东西变得可传递。**

- 单产品层：产品全景图（隐性 → 显式），回答"这个产品长什么样"。
- 组合层：产品组合视图，回答"所有产品处于什么状态、下一步做什么"。

## 核心设计

### 模型层级

```
产品组合 → 产品 → 用户故事地图 → 用户活动 → 用户任务 → 用户故事
```

决策发生在组合层，执行发生在产品层，两层通过钻取连通：在组合视图上做出决策，向下钻取到具体产品的故事地图验证可行性。

### 视图体系

| 视图 | 回答的问题 | 载体 |
|------|-----------|------|
| 组合视图 | 所有产品处于什么状态？投入如何分配？ | PortfolioView（规划中） |
| 产品空间 | 这个产品的需求与规格是什么？ | 产品切换器 + 空间侧边导航（需求 / 规格） |
| 产品全景视图 | 这个产品的用户旅程长什么样？ | 需求模块：StoryMapCanvas 看板 |
| 文档视图 | 产品的需求、设计与架构细节？ | dev-guide 文档站 |

> 产品空间参考项目管理软件：每个产品对标一个项目，顶部切换器（Switcher）切换；空间内需求模块为用户故事地图看板，规格模块计划使用事件风暴。

### 决策机制

- **产品目录**：登记产品、状态与负责人，形成产品清单。
- **MVP 发布线**：单产品版本范围的边界，可拖动调整。
- **版本计划**：产品的迭代节奏。
- **决策记录**：每个决策关联产品与依据，"为什么做这个"可追溯。

### 不变的原则

- **隐性 → 显式**：产品结构以共享视图存在，而非个人头脑。
- **领域模型与 UI 组件分离**：数据层（UserActivity / UserTask / UserStory）与视图层（ActivitySection / TaskColumn / StoryCard）命名与职责分离。
- **对照**：对照是认知工具——好与坏对照、产品与产品对照。跨产品对照是组合层新增的对照维度。
