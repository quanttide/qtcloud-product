## 多产品集中管理与可视化平台

> 2026-08-16

### 背景

量潮的产品越来越多，产品决策越来越困难。

单产品的全景图（用户故事地图）解决的是"一个产品长什么样"。但当产品数量增长，决策的难点从产品内部转移到产品之间：

- **做什么**：候选产品越来越多，先做哪个、停哪个？
- **投多少**：资源（人力、时间、资金）如何在产品之间分配？
- **何时做**：各产品的版本节奏如何对齐？
- **依赖什么**：产品之间共享哪些能力，先后顺序如何？

产品越多，决策越难——因为没有一个地方能看到所有产品的全貌。

### 需求

需要一个平台，集中管理和可视化所有产品：

- **集中管理**：所有产品的结构（故事地图、PRD、版本计划）、状态与决策记录集中沉淀，不再散落在各产品各自的文档里。
- **可视化**：产品组合视图——一个画布看到所有产品及其关系、成熟度、投入与版本边界，支撑跨产品的判断与决策。

### 与用户故事地图的关系

用户故事地图是单产品的"叶子"，组合视图是它的上一级：

- 单产品：用户活动 → 用户任务 → 用户故事
- 多产品：产品组合 → 产品 → 用户故事地图

决策发生在组合层，执行发生在产品层。平台让两层连通：在组合视图上做出决策，向下钻取到具体产品的故事地图验证可行性。

### 第一批实验对象

**qtcloud-devops、qtcloud-product、qtcloud-code** 作为第一批实验对象：

| 产品 | 形态 | 说明 |
|------|------|------|
| `qtcloud-devops` | CLI 工具链 | 量潮 DevOps 研发工具（release 等命令） |
| `qtcloud-product` | 文档 + Studio | 产品研发领域，产品云自身（自举实验：用产品云管理产品云） |
| `qtcloud-code` | CLI 工具链 | 代码研发领域工具 |

三者覆盖工具链、领域文档与画布客户端三种形态，规模适中，适合验证组合视图与集中管理能否支撑跨产品决策。

### 演化路径

1. 单产品故事地图稳定可用（当前阶段）。
2. 产品目录：登记产品、状态与负责人，形成产品清单。
3. 组合视图：跨产品可视化——成熟度、投入分布、版本时间线。
4. 决策记录：每个决策关联产品与依据，"为什么做这个"可追溯。
